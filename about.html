About Baseline UI

Purpose, design philosophy, and project identity

What This Is

Baseline UI is a minimal, framework-free website template built according to Material Design guidelines. It prioritises clarity, performance, and plain web standards — no build chain, no dependencies, no lock-in.

Every resource loads from public, widely available sources. The entire project lives in plain text files you can read and edit in any editor.

Design Principles

  • One language only — Standard HTML, CSS, and JavaScript. No preprocessors or compilers.
  • Variable-first typography — Single-file font families with continuous weight/width axes instead of multiple static files.
  • Icons as glyphs — Material Symbols only; no emoji, no image sprites.
  • Scope separation — Shared styles in one file; page-specific styles in separate files. No cross-contamination.
  • Strict licensing — Code and text carry distinct terms. Commercial use and derivative text content are restricted.
  • Flat file structure — Everything in root. No subfolders, no complex paths.

Supported Writing Systems

Core pages are optimised for:

  • Latin — Full coverage including diacritics
  • Vietnamese — Additional tone marks and extended Latin characters

Arabic is not included in the current font configuration.

Naming & Identity

The name Baseline UI and identifier baseline-ui belong to this original source repository. They are not open for adoption by forks or derivative projects. If you redistribute modified versions, you must use a distinct name and clearly link back to this location.

This policy exists to prevent fragmentation and impersonation, not to restrict the use of the code itself — which is MIT-licensed.

About the VFP

The Variable Font Playground is a self-contained experimental tool built into the site. It extends the base font set and runs an independent parser and renderer so typographic exploration does not affect the rest of the site.

Commands are stripped before display — only the visual result appears. This demonstrates how variable fonts can be manipulated through CSS properties and font axes in real time.

Future Directions

New pages may be added as needed, but the project will remain intentionally small and dependency-free. Features that require external tools or package management will not be accepted.

Planned additions include structured colour reference and component examples — these will follow the same file-per-page, flat-directory pattern.
